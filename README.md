# 智造未来 · SmartFactory Nexus

基于数字孪生与增强现实的智能柔性制造车间协同管控系统。研究生课程《工业智能制造系统设计与初步验证》可交互原型。

当前 `develop/v1.2-process` 分支已将十九阶段工序接入统一引擎：新增有界投料/缓冲、共享检测与转运、按合格入库完成订单，以及设备详情中的实时工序。见 [工序接入检查点](docs/14-v1.2工序接入.md)。完整机械动作与设备内部观察继续开发中；正式发布快照仍为下述 v1.1.1，可通过 Git 标签与 GitHub Releases 获取。

## 当前版本：v1.1.1

移除更新相关时间，统一主题色效果，并新增四档界面字号。变更与验证见 [v1.1.1 外观修正](docs/09-v1.1.1外观修正.md)。上一版的排产时间和设备灯座修正继续保留。从原版升级可直接替换源码并刷新，保留已有本地模拟记录；`dist/` 为更新后的生产构建。

## 启动

Windows 可双击项目根目录的 **启动系统.cmd**，安装缺少的依赖后自动打开浏览器。也可以使用下方命令。

要求 Node.js **22.12+**（已使用 22.23.4 验证）、npm、支持 WebGL 的现代浏览器。

```powershell
cd "D:\MY Data\Chatgpt ws\2026-11-09\files-pasted-by-the-user-codex\outputs\smartfactory-nexus"
npm ci
npm run dev -- --port 5174
```

访问 http://127.0.0.1:5174 。支持 hash 路由，AR 入口为 `/#ar`。项目仅在本地开发，未发布到互联网。

```powershell
npm run build
npm run preview -- --port 4173
npm test
npm run test:e2e
```

生产预览：http://127.0.0.1:4173 。`dist/` 可部署到任意支持 HTTPS 的静态主机。不要双击 HTML 使用 file 协议打开。

`test:e2e` 默认使用本机 `C:/Program Files/Google/Chrome/Application/chrome.exe`。其他电脑请修改 `playwright.config.ts` 的 `executablePath`，或安装 Playwright Chromium 并删除该配置。测试会自行启动 5174 开发服务或复用现有服务。

## 已实现功能

| 页面 | 实际交互 |
|---|---|
| 智能驾驶舱 | 统一 KPI、产线筛选、时间窗口、产量与能耗趋势、事件定位 |
| 数字孪生 | 真正 Three.js 场景、旋转平移缩放、选中高亮、平滑聚焦、预设视角、标签开关、低画质 |
| 生产调度 | 新建/编辑/取消订单、优先级、FCFS 与紧急优先、甘特图、负载与延期 |
| 质量检测 | 模拟抽检、缺陷分类、历史记录、批次筛选、产品标注与追溯 |
| 设备健康 | 实时参数、健康分、温度/振动采样曲线、三种异常注入、规则建议 |
| 能耗管理 | 三种功率/产能模式、分线与分设备用电、单位能耗、碳排假设估算 |
| AR 巡检 | MindAR 图像识别、摄像头启停、真实目标资源、设备叠加、三步维修与普通三维回退 |
| 系统设置 | 真实部署版本检查、明暗与主题色、画质/标签/倍速、表格密度、备份与偏好恢复 |
| 数据报告 | 时间筛选、指标切换、事件排序搜索、CSV/JSON/可打印 HTML 导出 |

故障会阻止需要该设备的工序或转运，保留当前工件和进度；上下游受资源与缓冲容量约束，完整交付路径受阻时不再显示确定完工时间。创建维修工单后，必须完成三个确认步骤才能恢复。历史告警和维修事件始终保留。

## 演示

1. 重置演示 → 初始化正常生产，开始生产，选择 20×。
2. 查看三维车间，选择 CNC-01，旋转视角并聚焦。
3. 生产调度 → 新增紧急订单，比较两种调度策略。
4. 设备健康 → CNC-01 → 注入温度异常。
5. AR 智能巡检 → 创建设备维修工单 → 完成三项检查 → 恢复生产。
6. 数据报告 → 搜索故障事件 → 导出运行报告。

完整 7 分钟讲稿见 [docs/04-课堂演示脚本.md](docs/04-课堂演示脚本.md)。

## AR 使用

- 本地库：`public/ar/`，MindAR **1.2.5** 与独立 Three.js **0.151.3**，不依赖外部 CDN。
- 自制识别图：`public/ar-targets/equipment-target.png`。
- 官方编译器实际生成：`public/ar-targets/equipment.mind`（不是占位文件）。
- 重新生成：先运行本地 5174 服务，再执行 `node tests/compile-target.mjs`。
- 手机需通过 **HTTPS** 访问。手机访问电脑局域网 HTTP 地址不具备摄像头权限安全上下文；电脑的 localhost 例外不适用于手机。
- 用另一台屏幕显示目标图，或完整打印。Android 用 Chrome，iOS 用 Safari，授权后对准完整识别图。
- 无摄像头或拒绝权限时显示原因，可进入明确标注的“普通三维维修演示”。该回退不具备 AR 识别能力。
- **待手机实机验证**。自动化验证了桌面合成视频流中的实际目标识别、媒体轨道释放、权限错误与回退流程，不能证明真实手机的跟踪精度。

## 数据、指标与简化

纯前端 Zustand 单一状态。每墙钟秒推进 1/5/20 个模拟秒，内部按工序、转运、计划开工与采样边界切分。初始日期固定为 2026-11-09 08:00，中国标准时间。随机种子 42，用于新投料工件的演示定位偏差。刷新后恢复主要状态并暂停运行。

两组加工单元采用同一演示工艺模板，每件标准流程 49 秒，转运 3 秒；QC-01 和 ASRS-01 为共享资源，物流停机可通过缓冲区产生上游等待。加工完成、生产检测和合格入库分别计数，抽检复用已有工件。三维机械体仍是简化演示模型，新的取放关节、机床门和刀具动作尚未接入。

原始设计见 [docs/02-初步设计.md](docs/02-初步设计.md)，本开发分支的流程与统计变化以 [工序接入检查点](docs/14-v1.2工序接入.md) 为准。所有数据均为模拟，未接入 PLC。检测值来自工艺参数与演示规格，示意框不是图像识别结果。维护建议来自阈值规则，未训练 AI 模型。碳因子 **0.57 kgCO₂/kWh** 仅为演示假设。

本地存储键 `nexus-simulation-v1`。演示数据较大或浏览器存储受限时可重置。事件保留最近 2000 条，设备曲线保留最近 180 点。项目不提供服务器、多用户同步、账户权限或真实生产控制。

## 项目目录

`src/domain` 数据模型，`src/simulation` 确定性模拟与调度，`src/store` 应用动作和本地持久化，`src/pages` 八个业务页面，`src/features/digital-twin` 程序化车间，`src/components` 图表和通用控件，`public/ar` 独立 AR 生命周期，`tests` 单元与浏览器验收，`docs` 课程文档，`deliverables` 答辩与截图。
