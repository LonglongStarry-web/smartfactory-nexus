# 需求分析

## 背景与范围

本项目面向研究生课程的设计与初步验证，模拟一个具有两条柔性制造产线的实验车间。优先实现可重复演示、跨页面一致和可解释的制造协同流程。成果是浏览器课程原型，不具备真实工业控制能力。

## 工业场景与问题

车间接收多产品小批量订单。设备可用性、紧急插单、缺陷和能耗共同影响履约。传统分散表格难以同时回答“哪个设备故障、哪个订单受影响、维修后何时恢复”。现场人员需要将设备身份、状态和维护步骤联系起来。课程以统一事件状态和数字孪生表达该关系，AR 为现场信息叠加提供实验入口。

上述场景为课程设计假设，尚未开展真实工厂访谈。没有宣称已验证行业痛点的普遍程度，也没有引用未经调查的效率提升百分比。

## 目标用户

| 用户 | 工作任务 | 原型支持 |
|---|---|---|
| 车间调度员 | 查看订单、处理插单、比较策略 | 订单 CRUD、规则排产、甘特图 |
| 设备维护员 | 定位故障、检查建议、执行维修 | 三维选择、阈值诊断、三步工单 |
| 质量工程师 | 查看缺陷与批次 | 模拟质检、分类和追溯 |
| 生产主管 | 了解产出、质量、能源和履约 | 驾驶舱与可导出报告 |
| 课程评审 | 重复运行演示并核对证据 | 场景重置、固定种子、测试记录 |

## 非功能需求

- 可运行性：安装依赖、启动和生产构建可重复执行。
- 可解释性：显示 OEE 口径、模拟阈值、碳因子与业务简化。
- 一致性：设备 ID、订单 ID、事件 ID、时间戳来自同一状态，不让各页面自行随机生成数据。
- 可用性：每页至少一种真实交互，重要取消/重置需要确认，非法参数阻止提交。
- 视觉：统一深色蓝灰、青色强调与状态色，导航在手机收起，表格局部滚动。
- 性能：程序化几何、受控灯光、低画质、图表 ResizeObserver 与卸载 dispose。
- 隐私：模拟状态留在本浏览器，不上传摄像头画面，未注册外部服务。
- AR：安全上下文、权限提示、媒体流关闭、真实手机验证与桌面验收分开。

## 典型用户故事

调度员开始生产，看到订单逐件完成。紧急订单进入后，优先调度改变其起始时刻。维护员注入 CNC-01 温度异常，该线停机、告警新增且剩余订单转交可用设备。维护员在 AR 页创建工单，按三项步骤确认后恢复。主管导出报告，保留故障和维修历史。

## 范围边界

不开发 PLC 协议、真实相机缺陷检测、训练型预测模型、物理仿真、生产级 MES、安全联锁认证或多用户服务器。模型将一条产线的加工抽象到一台 CNC，其他工位提供协同状态与动画，不声称真实工艺仿真精度。


## v1.3 需求细化与交付映射

- 工序可解释性：能观察内部切削、夹持交接与检测；历史参数和配方不被新设置覆盖。
- 可复现质量：三类参数场景对应明确规格判定；支持隔离、报废和限定的去毛刺返工。
- 柔性制造：两种真实区分的演示配方、设备兼容能力、换型时间、未开工毛坯故障转运。
- 物流守恒：缓冲容量、独占转运、满仓反压及发运；不将加工完成冒充合格入库。
- 独立评阅：23 页最终演示文稿覆盖需求、初步设计、原型与初步评估，无需现场讲解。

课程说明的四周是作业允许周期，本项目不将其表述为已完成四周现场研究。现阶段评估是可重复技术验证，真实用户与专家评估另列计划。
