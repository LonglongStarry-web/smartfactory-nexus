# AR 实机测试清单

**当前结论：待手机实机验证。** 本机 Chrome 自动化已使用目标PNG合成视频流实际完成MindAR目标识别，且关闭后测试轨道全部释放。这不涉及实体摄像头，不能替代手机验收。

## 操作

1. `npm run build`，将 `dist` 放到 HTTPS 静态主机。所有文件保持目录结构。
2. 在 Android Chrome 和 iOS Safari 分别打开 `/#ar`。
3. 用电脑显示或完整打印 `public/ar-targets/equipment-target.png`。
4. 手机点击“启动 AR 摄像头”，允许权限，对准目标。
5. 观察“已识别目标”状态与简化 CNC 模型叠加；移动目标、遮挡后重新识别。
6. 在故障场景创建维修工单，确认步骤、恢复，检查事件同步。
7. 关闭摄像头或切换页面，确认系统摄像头指示熄灭。

## 目标资源与许可

自制 700×900 PNG，通过实际运行的 MindAR 1.2.5 Compiler 编译出二进制 `.mind`。可用 `node tests/compile-target.mjs` 复现。运行库本地保存，MindAR 与 Three.js MIT 许可附在 `public/ar/`。第三方代码保留原始许可头。

## 已知边界

同一目标图用于选中设备的演示身份绑定，不代表每台实体设备具有独立识别标记。模型为简化 CNC，不因选中机器人而变成真实机器人模型。需要扩展多目标编译与目标索引映射才能形成真实多设备巡检。识别性能、iOS 生命周期和现场可读性必须由实机记录证明。
