# 版本归档与后续开发

Git 历史由已有的三个原始交付包恢复。每个版本单独提交并打注释标签；提交说明保留交付包 SHA-256。归档提交表示从版本包重建的快照，不表示原开发期间已经使用 Git。

| 标签 | 内容 | 归档提交 |
|---|---|---|
| v1.0.0 | 首版课程原型、三维车间、AR 巡检与课程材料 | 933c158526b8fd0322e9ff966607d9d02c5ddc37 |
| v1.1.0 | 排产时间修正、设备指示灯安装、系统设置 | 2a775700eff0b568bfbbaaaf3120aa029080b1bc |
| v1.1.1 | 移除更新时间、主题色生效、四档字号 | d3c5bd901d1057fa9fde248214cb618302bc714a |

源码、依赖锁文件、资源、文档与课程材料纳入版本控制。`node_modules`、`dist`、测试运行缓存和 Office 临时锁文件不纳入 Git。原始交付包作为 GitHub Release 附件保留，包含交付时的构建产物和验证记录。版本包校验值见 `version-archives.sha256`。

后续开发从已备份的 main 分支创建功能分支，提交工序引擎、机械动作、内部观察和质量追溯等可检查的变更。通过对应测试后再形成新的版本标签及发布包。已有版本标签保持固定，旧版存档和用户偏好需要兼容。

在新的工作目录查看旧版：

```powershell
git worktree add ../smartfactory-nexus-v1.1.0 v1.1.0
```

新工作目录按该版本锁文件执行 `npm ci`，随后使用其启动入口。Git 仓库记录源码备份，不等同于网站已经在线部署。
