# SmartFactory Nexus 下一阶段开发计划

本文保留 v1.1.1 完成后、v1.2 开发前的阶段计划。后续实现及验证见文档 13–18。

目标：机械动作能对应实际工序；点击设备可以观察加工过程；点击不合格品可以沿记录解释检测结果；多品种与调度变化能体现柔性制造。

品牌沿用“智造未来 · SmartFactory Nexus”，界面简称建议为“柔性制造数字孪生平台”。正式副标题建议采用“基于数字孪生与 AR 的柔性制造过程可视化与协同管控系统”，随功能交付统一到界面、报告与课程材料。

## 1. 开发基线与技能使用

现有技术栈保持 React、TypeScript、Zustand、Three.js、React Three Fiber、Drei 和 ECharts。本机实际安装版本为 Three.js 0.180.0、Fiber 9.8.2、Drei 10.7.9、React 19.3.1、Zustand 5.1.0；package.json 声明的是版本范围，不能将范围下限当作实际安装版本。

技能核查结论与来源见[技能核查记录](12-Skills核查记录.md)。基础界面与测试沿用已有技能；社区 3D 技能作为可复用候选，需要在当前版本和真实页面中验证；工艺及质量管理技能提供设计参考，具体仿真规则、状态推进与统计仍由项目实现。

开发开始时，通过官方 skill-installer 将选定社区技能及其必要引用放入工作区 skills 目录，固定上游提交并记录来源。按任务读取相关技能，先完成最小兼容性验证。CloudAI-X 的部分示例面向 Three.js r186，采用其中方法时核对本项目 r180 的接口，保持由 Fiber 管理 Canvas 与帧循环。

本阶段采用工序驱动的运动学与质量规则仿真。工件形态先用分阶段几何与刀具路径表达。真实材料去除、切削力和设备精度标定需要额外数据，作为以后单独扩展的范围。

## 2. 阶段与交付顺序

| 阶段 | 开发内容 | 可检查的结果 |
|---|---|---|
| P0：建立工艺与工件基础 | 产品工艺、单件身份、设备能力、缓冲位、工序状态机、统计口径、存档迁移 | 同一件工件的状态、位置、工序和计数只有一套来源 |
| P1：完成单元机械动作 | CNC-01、ARM-01、QC-01 与相邻输送/分流；先完成一种法兰件 | 能跟随同一件工件看完上料、加工、检测和分流 |
| P2：设备内部观察 | 设备详情入口、内部视角、工序说明、刀具路径、参数、独立回放 | 点击 CNC 能看加工，点击机械臂能看取放，点击 QC 能看检测依据 |
| P3：质量因果与追溯 | 至少三个可复现异常场景、尺寸/特征检测、来源追溯、调整后对比 | 每个不合格结果都有实测仿真值、规格、触发规则和过程记录 |
| P4：v1.2 集成验收 | 跨页面统计、故障恢复、倍速、设置、兼容性、性能与回归 | 交付可运行版本、演示脚本、检查结果与完整开发包 |
| P5：v1.3 柔性与物流扩展 | 两种产品工艺、能力约束、换型、插单与改派、AGV、仓储 | 能看到产品变化和设备异常如何改变工艺、排程及物流 |

按 P0 → P1 → P2 → P3 → P4 → P5 推进。每一阶段完成可演示结果和对应检查，再扩展范围。P0 完成后，根据样板单元实测复杂度细化工作量，不预先承诺未经验证的交付时长。

## 3. P0：先统一工序、工件与统计

设计产品配方、工序定义、运行中的工序、工件状态、工位锚点及检测记录。第一种产品先使用法兰件，设定装夹、端面处理、轮廓加工、钻孔、去毛刺与检测等演示步骤；顺序与参数作为明确的仿真配方。

工件从投料时生成唯一 ID，而不是等检测完成再生成。每件工件记录订单、产品配方版本、当前位置、当前持有设备、当前工序、阶段进度、参数快照及事件记录。任一时刻只能处于一个位置，并由一个资源持有；空夹爪不得运送工件，未到位不得开始下一步。

引擎推进业务状态，三维场景读取状态并插值显示。采用统一模拟时钟，保留现有倍速和暂停功能。渲染帧回调不产生产品、不重复计数。大时间步要处理跨过的全部工序边界，后台恢复也采用同一推进策略。

统计分别呈现加工完成、在制、待检、检验合格、不合格、合格入库和交付完成。订单需求以合格入库件数满足为完成条件；返工复检不重复累计产量，报废需按规则补投。取消订单时，已投料工件保留身份并进入明确处置状态。正常流转、缓冲满位和无可用设备都应显示原因。

预计完成时间依据剩余工序、当前进度、资源占用和已知待补数量计算。尚未发生的质量损失只作为注明假设的风险估计，不输出虚假的确定时间。无可行路径时显示阻塞原因。

存档数据升级时保留旧记录和用户主题、字号等偏好。旧版记录缺少加工轨迹，标记为“历史记录，无工序明细”，不补造因果。旧版订单完成口径单独标注；新订单使用新统计规则。刷新恢复时保持暂停并展示已恢复状态。

## 4. P1：让机械动作有具体任务

第一组完整单元：CNC-01、ARM-01、QC-01、上下料位、输送段及良品/不合格暂存位。先检查机械臂长度、设备间距、抓取面、夹具位置与可达范围，再制作动画。

完整循环：毛坯到位 → 接近并抓取 → 开门上料 → 工件定位并夹紧 → 夹爪松开并撤离 → 关门加工 → 退刀并停止加工动作 → 开门卸料 → 移交检测 → 合格/不合格分流。

机械臂具备底座、肩、肘、腕和夹爪的协调动作。先用经过可达性检查的关键姿态和轨迹实现，必要时补充逆运动学。抓取、夹紧、释放的工件归属在明确事件点切换，保持世界位置连续。

CNC 增加可移动门、工作台、夹具、主轴与可见刀具；刀具路径与当前工序关联，显示毛坯到成品的阶段变化。视觉辅助只在相应工序启用，并支持减少动态效果。

QC 增加工件定位、扫描/测量动作和结果分流。输送段按实际工件位置、接收位是否空闲决定移动。设备等待、故障、维修会阻止相关转移；工件保留在故障发生的位置，恢复后从有效阶段继续。

该阶段检查工件与夹爪、工件与夹具的接触关系，避免悬空、明显穿模及跳跃。检查是演示轨迹的几何与状态一致性检查，不代表完成工业碰撞安全认证。

## 5. P2：点击设备观察内部加工

沿用三维点击和设备列表选择，设备概览提供“观察加工”入口。进入后保留设备、工件和订单标识，并能清楚返回车间视图。

| 对象 | 主要观察内容 |
|---|---|
| CNC | 外观/内部视角、机壳半透明、夹具和工件、当前刀具、加工路径、工序进度、带单位参数 |
| 机械臂 | 本次取放任务、抓取/放置位置、夹爪开合、工件持有状态、等待原因 |
| QC | 检测项目、名义值、允许范围、测量值、判定结果、检测特征标记 |

工序说明随实际阶段切换。设置面板可控制路径和辅助标记显示，字号、主题色和减少动态效果沿用全局偏好。移动端以观察区和明细页签切换，提供设备列表作为三维点击的替代入口。

实时观察跟随生产。历史回放读取参数与事件快照，提供暂停、慢放及逐步查看；回放不修改生产数据、不增加产量和能耗。没有历史轨迹时显示缺失状态。

## 6. P3：质量结果对应过程证据

检测记录增加特征编号、名义值、公差/阈值、仿真测量值、判定依据、测量噪声设定、加工设备和工序、规则版本与参数快照。

至少完成以下三个明确标注为演示规则的场景：

| 场景 | 参数与结果的连接 | 可看到的说明 |
|---|---|---|
| 装夹基准偏移 | 定位偏移进入孔位坐标的计算，再与允许范围比较 | 对应孔位高亮，显示装夹阶段记录与坐标超差 |
| 加工补偿偏差 | 明确的尺寸补偿规则改变目标轮廓尺寸，再进行尺寸判定 | 显示补偿设定、计算规则和尺寸偏差 |
| 漏去毛刺 | 配方中的去毛刺步骤被设为异常跳过，模拟残余特征超过阈值 | 标记残余特征，显示跳过事件及检测阈值 |

例：孔位 X 的名义值为 20.00 mm，允许偏差 ±0.05 mm；演示模型设置定位偏移 +0.08 mm，先在无测量噪声的场景下得到 20.08 mm，结果为孔位超差。数值用于检验规则是否一致，不作为真实加工参数建议。

不再独立随机抽取缺陷名称。随机扰动若保留，应有种子、幅值和作用位置；质量由参数与测量规则计算。异常设置只在定义的后续工序生效，已有工件和历史结果使用各自快照。

质量页面可以由检测记录定位到设备、工序及当时参数。区分“规则模型中已知的触发条件”和“待验证的可能原因”；信息不足时说明缺少哪些证据。调整参数后对比后续新工件，历史结果保持原记录。处理路径先实现隔离、指定工序返工并复检、报废补投。

## 7. P4：v1.2 验收与交付

| 检查范围 | 通过条件 |
|---|---|
| 工件与流程 | 同一 ID 完成全过程；缓冲位不超容量；没有复制、丢失或无来源工件 |
| 倍速与暂停 | 1/5/20 倍速得到一致的事件顺序；暂停不推进工序；跨阶段不漏检或重复完成 |
| 故障与恢复 | 抓取、加工、检测阶段分别注入故障，恢复后工件位置、状态和计数一致 |
| 质量 | 正常与三个异常场景可重复；阈值边界及随机种子受控；历史记录可追溯 |
| 调度与指标 | 在制、待检、良品、废品及交付口径可核对；ETA 和报表使用相同来源；人工复检不增加产量 |
| 数据兼容 | 旧存档加载、旧记录缺少轨迹、刷新恢复和导出都能正确处理 |
| 页面交互 | 进入观察、返回、筛选、回放、主题色与最大字号在桌面和平板/手机可用 |
| 三维效果 | 连续观察至少 10 个循环，重点检查夹持接触、交接位置、刀具路径、遮挡和明显穿模 |
| 性能与资源 | 记录设备、浏览器、分辨率、渲染后端、帧时间、绘制调用及重复进入后的资源趋势 |

验证工具采用现有 Vitest 与 Playwright 回归，加上针对三维空间关系的断言及真实浏览器视觉检查。运行构建与完整相关回归；用实际阶段截图或短视频作为机械动作证据，不能仅凭业务数值断言动画正确。

性能先测基线，再控制阴影、像素比、几何复用与细节层次。桌面以流畅交互为目标，在记录测试条件后设定预算；软件渲染环境用于功能与截图验证，单独标注，不能替代实际 GPU 的性能结论。

交付：可运行源码与本地启动入口、v1.2 开发包、技能与模型来源记录、工艺/质量规则说明、检查报告、三类异常演示脚本及实际界面截图。界面版本信息沿用不记录更新时间的要求。课程文档和已有答辩材料按实际实现内容同步。

## 8. P5：v1.3 扩展全车间与柔性制造

在样板单元验收后，将流程推广到第二组设备，并至少定义两种不同工艺配方。产品差异应影响工序顺序、刀具或夹具、周期与检测项目，不能只改变订单名称。

给设备定义可加工能力、适用配方及换型成本。排产考虑有限资源、正在加工的工件、换型、缓冲和合格需求；插单不任意抢走已装夹工件。故障后只有满足能力、工装和物流条件的设备才能接收改派，并显示改派前后路径与预计完成变化。

AGV 从往返摆动升级为有任务的路径移动：到站、减速、停车、握手、装卸、离站。仓储加入明确库位、搬运升降和库存变化。物流任务对应真实工件或容器 ID，并处理站点占用和通路冲突。

AR 继续使用现有 MindAR 识别路线，后续可读取设备工序与异常记录。WebXR 技能只能提供另外一种 XR 技术路线的参考，不能直接替换当前图像识别。实机跟踪效果与桌面模拟验证分别报告。

## 9. 实施落点

预计主要涉及 `src/domain/types.ts`、`src/simulation/engine.ts`、`src/store/useFactory.ts`、`src/features/digital-twin/`、`src/components/DeviceDetail.tsx`、质量/排产/报表页面及对应测试。

工艺定义、阶段推进、检测规则与回放快照拆成可独立检查的模块；先完成业务状态及数据迁移，再连接动作和详情页面，最后扩展全车间。资源只按需要引入，模型需包含可分离的部件、关节轴和取放锚点；第一阶段优先增强现有代码模型，外部模型经结构与许可检查后再使用。

下一项具体开发任务：产出第一种法兰件的工序表、设备/工件状态转换表、工位锚点布局，以及在制/待检/合格入库的计数契约，并实现最小可运行的工序推进。
